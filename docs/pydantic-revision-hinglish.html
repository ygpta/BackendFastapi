01 · Shuruaat

Pydantic ka kaam kya hai?

Pydantic Python ke type hints ko program chalte waqt use karke input ko padhta aur check karta hai. FastAPI request ka JSON Pydantic model ko deta hai. Data theek ho to endpoint ko Python object milta hai; data galat ho to aam taur par HTTP 422 response aata hai.

from pydantic import BaseModel

class TicketInput(BaseModel):
    subject: str
    message: str

ticket = TicketInput.model_validate({
    "subject": "Login issue",
    "message": "I cannot log in today.",
})

print(ticket.subject)  # Login issue

02 · Field ke rules

Field se kya karte hain?

Field se kisi value ki lambai, number ki seema, default value aur documentation ki jaankari de sakte ho.

from pydantic import BaseModel, Field

class TicketInput(BaseModel):
    subject: str = Field(min_length=1, max_length=120)
    message: str = Field(min_length=10, max_length=4000)
    customer_reference: str | None = Field(
        default=None,
        min_length=1,
        max_length=64,
    )
  • str | None ka matlab value string bhi ho sakti hai aur None bhi.
  • = None dene se request mein ye field bhejna zaroori nahi hota.
  • list[str] = Field(default_factory=list) har naye model ke liye alag khaali list banata hai. Seedha = [] default mat do, warna models ke beech list share ho sakti hai.
03 · Model ki settings

model_config: poore model ke niyam

model_config Pydantic ko batata hai ki is model ke saare input ke saath kaise pesh aana hai. Ye input ka field nahi, model ki setting hai.

from pydantic import BaseModel, ConfigDict

class TicketInput(BaseModel):
    model_config = ConfigDict(
        str_strip_whitespace=True,
        extra="forbid",
    )

    subject: str
  • str_strip_whitespace=True: " Login " ke aage-peeche ki khaali jagah hata kar "Login" banata hai.
  • extra="forbid": model mein na diye gaye keys, jaise admin, bhejne par error aata hai.
  • from_attributes=True: dictionary ke saath-saath Python/SQLAlchemy object ke attributes, jaise record.id, se bhi values padhta hai.
Dhyan rahe: Pydantic ka input check login ya permission check nahi hai. extra="forbid" anjaan input key ko rokta hai; ye nahi jaanchta ki user admin hai ya nahi.
04 · Apne validation rules

field_validator aur model_validator

Sirf ek field ke liye: field_validator

from pydantic import BaseModel, field_validator

class TicketInput(BaseModel):
    subject: str

    @field_validator("subject")
    @classmethod
    def clean_subject(cls, value: str) -> str:
        value = value.strip()
        if not value:
            raise ValueError("Subject khaali nahi ho sakta")
        return value

Ye rule sirf subject ko saaf karta hai aur dekhta hai ki woh khaali to nahi. Badli hui value ko return karna zaroori hai; wahi aage model mein jaati hai.

Do ya zyada fields ko saath check karne ke liye: model_validator

from datetime import date
from pydantic import BaseModel, model_validator

class Booking(BaseModel):
    start_date: date
    end_date: date

    @model_validator(mode="after")
    def check_dates(self):
        if self.end_date < self.start_date:
            raise ValueError("End date, start date se pehle nahi ho sakti")
        return self

mode="after" mein dono fields parse hone ke baad validator ko poora model milta hai. Isliye yahan dono dates ki tulna kar sakte hain.

05 · Ek model ke andar doosra model

Nested model: Customer ka Address

Jab ek model ke andar doosre model ka data rakhna ho, nested model banao. Customer khud Address nahi hota; Customer ke paas Address hota hai.

from pydantic import BaseModel

class Address(BaseModel):
    city: str
    country: str

class Customer(BaseModel):
    name: str
    address: Address

customer = Customer.model_validate({
    "name": "Asha",
    "address": {"city": "Delhi", "country": "India"},
})

print(customer.address.city)  # Delhi

Customer(Address) likhne se city aur country Customer ke seedhe fields ban jaate hain. Address ko andar rakhna ho to address: Address likho, jaise upar ki class mein hai.

06 · Fields dobara istemal karna

Inheritance: common fields share karo

Agar create request aur response mein kuch fields same hon, to unhe base model mein likhkar dono models mein inherit kar sakte ho.

from pydantic import BaseModel, SecretStr, Field

class UserBase(BaseModel):
    name: str
    email: str

class UserCreate(UserBase):
    password: SecretStr = Field(min_length=12)

class UserResponse(UserBase):
    id: int

UserCreate ko base se name aur email milte hain; usmein password bhi hai. UserResponse ko wahi common fields aur ID milti hai, password nahi.

Inheritance tab use karo jab models ke kuch fields same hon. Ek model ke andar doosra model rakhna ho to nested field likho: address: Address.
07 · Data ka aana-jaana

Deserialize aur serialize karna

Deserialization: dictionary/JSON se Pydantic object banana aur uske data ko check karna.

payload = {"name": "Asha", "email": "asha@example.com", "id": 42}
user = UserResponse.model_validate(payload)

json_text = '{"name":"Asha","email":"asha@example.com","id":42}'
user_again = UserResponse.model_validate_json(json_text)

Serialization: Pydantic object ko dictionary ya JSON text mein badalna.

python_dict = user.model_dump()
json_text = user.model_dump_json()

# None value wale optional fields hatane ke liye:
clean_dict = user.model_dump(exclude_none=True)
