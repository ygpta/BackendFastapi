04 / Durable AI run

AI job enqueue se streamed result tak

  • Durable run ek AI job hai jiska status database mein save rehta hai.
  • Client job submit karke response le sakta hai, phir status ya events baad mein dekh sakta hai.
  • Worker queue se job claim karke process karta hai.
Idempotency

Same request dobara aayi?

  • Client har intended submission ke liye ek unique key bhejta hai.
  • Network timeout ke baad wahi request retry karte waqt wahi key bhejo.
  • Server duplicate job/ticket banane ke bajay pehli submission ko pehchanta hai.
Lease

Worker crash ho gaya?

  • Lease ek worker ke paas job ka temporary ownership lock hai.
  • Worker crash ho to lease expire hoti hai aur doosra worker job reclaim kar sakta hai.
  • Lease token purane worker ki late database writes ko rokta hai.
Checkpoint

Har step ka state

  • Graph ke completed steps ka progress save hota hai.
  • Restart/crash ke baad recovery behtar ho sakti hai.
  • External action repeat na ho, uske liye idempotency/receipt phir bhi chahiye.
Boundary yaad rakho:
  • Checkpointing external action ko exactly once chalne ki guarantee nahi deta.
  • Is app ka ticket tool allowlisted hai aur alag admin approval maangta hai.
  • Receipt repeat local ticket update ko rokne mein madad karti hai.

08 / Design decisions

Code ko aisa kyun likha gaya?

1. Request handler patla rakho

  • Handler HTTP input leta hai aur service ko deta hai.
  • Business behavior ko fake DB ya direct service test se check kar sakte hain.
Socho:
  • Kal webhook bhi wahi use case chalaye to business logic duplicate na ho.

2. Startup mein shared clients banao

  • HTTP/LLM clients lifespan mein bante hain.
  • Connection pool requests ke beech reuse hota hai.
  • Shutdown par resources close hote hain.
Socho:
  • Har request par naya client banane se connections waste aur resource leaks ho sakte hain.

3. Sync aur durable chat alag

  • Inline /chat ek seedha response path hai.
  • /runs queue, idempotency, cancellation, events aur recovery deta hai.
Socho:
  • Chhoti chat ko job-system complexity nahi chahiye; lambi job ko HTTP connection par latkana theek nahi.

4. AI provider ko configurable rakho

  • Provider, model aur base URL configuration se badalte hain.
  • Workflow ko ek provider brand ke saath hard-wire nahi kiya.
Socho:
  • Ollama ya xAI/Grok chunne par poora workflow dobara likhna na pade.

5. RAG mein chunks kyun?

  • Poora bada document bhejne se context noisy aur mehnga ho sakta hai.
  • Chunks relevant passage dhoondhne mein madad karte hain.
Socho:
  • Ek paragraph jawab de sakta hai; poori kitab bhejne ki zaroorat nahi.

6. Hybrid search aur RRF kyun?

  • Vector search meaning ke kareeb text pakadta hai.
  • Lexical search exact words/codes pakadta hai.
  • RRF dono result rankings ko mila kar ek order banata hai.
Socho:
  • Product code exact match ho sakta hai; user ka paraphrase semantic match ho sakta hai.

7. Budget pehle reserve kyun?

  • Model call se pehle maximum expected cost reserve hota hai.
  • Concurrent requests same remaining balance overspend na karein, ismein madad milti hai.
Socho:
  • Billable call ke baad budget check karoge to rokne ke liye der ho chuki hogi.

8. Tests mein fake provider kyun?

  • Fake model se free aur repeatable tests chalte hain.
  • Response, failure, citations aur events provider call ke baghair verify hote hain.
Socho:
  • Paid network calls tests ko slow, costly aur flaky kar sakte hain.

Flush / rollback Flush pending writes DB ko bhejta hai, lekin transaction commit nahi karta. Rollback uncommitted changes cancel karta hai. Related records ko ek transaction mein jodte waqt; failure par partial writes save nahi honi chahiye. Run ID create hone ke baad event/replay records add hote hain; final commit durability boundary hai.
Connection pool / lifespan Pool reusable connections ka group hai. Lifespan app startup se shutdown tak resource setup/cleanup ka scope hai. Har request par connection/client dobara banane ka overhead bachane ke liye. Shared HTTP client startup par banta hai; har request ka DB session phir bhi alag hota hai.
Optimistic concurrency / version Update ke saath expected old version bhejkar check karna ki record meanwhile badla to nahi. Do users same ticket edit karein aur silent overwrite se bachna ho. Stale expected version par conflict milta hai; latest record padho, review karo, phir update bhejo.
Row lock / SKIP LOCKED Transaction row ko concurrent conflicting writes se lock karti hai; SKIP LOCKED already locked row ko wait karne ke bajay chhodta hai. Multiple workers queue se alag-alag jobs claim karein tab. Worker claim query PostgreSQL row lock leti hai; long generation ke liye lease alag ownership mechanism hai.
Upsert / unique constraint Upsert conflict par insert ke bajay defined update/no-op karta hai. Unique constraint duplicate key ko DB level par rokta hai. Concurrent callers same idempotency key ya rate bucket claim karein tab. Tenant + idempotency key unique hai; request hash alag ho to 409 milta hai.
Rate limit / budget Rate limit time window mein requests ki ginti cap karta hai; budget model spend/reservations ko cap karta hai. Traffic abuse aur cost control ke liye; dono alag problems hain. Shared DB counters aur monthly tenant budget. Embedding spend durable-run budget ledger mein included nahi hai.
CORS / TLS / proxy CORS browser ke cross-origin access rules hain; TLS transport encrypt karta hai; reverse proxy traffic app tak forward karta hai. Frontend alag origin par ho aur public HTTPS deployment chahiye ho. CORS authentication nahi hai. Production HTTPS gateway app se bahar configure hota hai.
Token / tokenizer / context Model text ko token units mein padhta hai; tokenizer un units ko count karta hai; context model ko diya input hai. Input/output limits aur cost estimate karne ke liye. Character count aur token count same nahi hote. Durable generation tiktoken se input bound check karti hai; selected model ka tokenizer support verify karo.
GIN / HNSW / cosine distance GIN text-search index hai; HNSW approximate nearest-vector index hai; cosine distance vector direction similarity ka measure hai. Large text/vector collections mein retrieval efficient banana ho tab. PostgreSQL full-text aur pgvector indexes. Fast lookup answer ki relevance/correctness guarantee nahi hai.
Webhook / batch / citation Webhook event-triggered HTTP call hai; batch ek request mein multiple items hai; citation answer ka source reference hai. External automation se jobs trigger karne, bounded jobs group bhejne, ya answer ke sources dikhane ke liye. Generic webhook JWT-protected hai; batch max 10 items; structured citation IDs retrieved documents se validate hote hain.
Cache / snapshot / fingerprint Cache reusable result rakhta hai; snapshot accepted configuration freeze karta hai; fingerprint input ka stable hash hai. Repeated work bachana, queued job ko later config changes se alag rakhna, aur matching retries pehchanna ho. Query embedding cache, run payload snapshot aur idempotency request hash teen alag uses hain.
Idempotency key ka short rule:
  • Ek user intention = ek key.
  • Ussi intention ka retry = purani key dobara.
  • Nayi intention = nayi key.
  • Example: run submit kiya, network timeout hua, status nahi pata—same payload aur same key se retry karo.
  • Same key ko different payload ke saath bhejne par app 409 Conflict deti hai; alag message/run ho to nayi key banao.

def split_document(content: str) -> list[str]:
    normalized = " ".join(content.split())
    chunks = []
    start = 0
    while start < len(normalized):
        end = min(start + CHUNK_SIZE, len(normalized))
        if end < len(normalized):
            boundary = normalized.rfind(" ", start + CHUNK_SIZE // 2, end)
            if boundary > start:
                end = boundary
        chunks.append(normalized[start:end])
        if end == len(normalized):
            break
        start = max(end - CHUNK_OVERLAP, start + 1)
    return chunks
  • Normalize: repeated whitespace ko collapse karte hain, taaki splitting consistent ho.
  • Size: har chunk maximum 1200 characters; yeh character limit hai, token limit nahi.
  • Boundary: mumkin ho to word boundary par chunk ka end rakhte hain.
  • Overlap: 150 characters repeat rakhte hain taaki passage ka context cut par na kho jaye.
  • Trade-off: overlap context bachata hai, lekin storage/embedding work badhata hai.

async def submit_batch(
    data: BatchRunCreate,
    session: Session,
    actor: Actor,
    settings: Annotated[Settings, Depends(get_settings)],
    response: Response,
    idempotency_key: Annotated[
        str, Header(min_length=8, max_length=100, pattern=r"^[A-Za-z0-9._:-]+$")
    ],
):
    key_prefix = hashlib.sha256(idempotency_key.encode()).hexdigest()[:48]
    results = []
    for index, item in enumerate(data.items):
        try:
            run = await submit_run(
                session,
                item,
                actor,
                f"batch-{key_prefix}-{index}",
                settings,
            )
            results.append(BatchRunResult(index=index, run=run))
        except HTTPException as exc:
            await session.rollback()

    if any(result.error is not None for result in results):

    return results
